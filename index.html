BM25 and Its Limitations

BM25 (Best Matching 25)

Unsupervised lexical scoring formula

$$\mathrm{BM25}(q,d)=\sum_{t\in q}\mathrm{IDF}(t)\cdot\frac{f(t,d)\,(k_1+1)}{f(t,d)+k_1\!\left(1-b+b\frac{|d|}{\mathrm{avgdl}}\right)}$$
TF term frequencyIDF term rarityLength normalization

No training, fast and strong baseline — but it only sees words.

1Exact keyword overlap

Misses synonyms and context

2Ignores quality signals

PageRank, domain authority, engagement

3Keyword stuffing

Vulnerable to SEO spam

4Manual tuning

100+ feature weights cannot be tuned by hand

RankNet methodology · 2 of 4

Score Difference and Sigmoid Probability

Pairwise score difference

$$o_{ij}\equiv o_i-o_j=f(\mathbf{x}_i)-f(\mathbf{x}_j)$$

Modeled posterior probability — logistic sigmoid maps $o_{ij}$ into $(0,1)$

$$P_{ij}=P(\mathbf{x}_i \triangleright \mathbf{x}_j)=\frac{e^{o_{ij}}}{1+e^{o_{ij}}}$$

Ground-truth target probability $\bar P_{ij}$

Relevance of the pair $\bar P_{ij}$
$\mathbf{x}_i$ more relevant than $\mathbf{x}_j$ $1$
$\mathbf{x}_j$ more relevant than $\mathbf{x}_i$ $0$
Equal relevance (tie) $0.5$

$P_{ij}$ as a function of $o_{ij}$

Large positive gap → near-certain that $i$ beats $j$.

RankNet methodology · 3 of 4

Cross-Entropy Cost Function

$$C_{ij}=-\bar P_{ij}\log P_{ij}-(1-\bar P_{ij})\log(1-P_{ij})=-\bar P_{ij}\,o_{ij}+\log\!\left(1+e^{o_{ij}}\right)$$
1Shift invariance

Depends only on $o_i-o_j$; a constant offset on all scores changes nothing

2Outlier robustness

Grows linearly, not quadratically like MSE — noisy labels do not blow up training

3Principled ties

With $\bar P_{ij}=0.5$ the minimum sits exactly at $o_{ij}=0$

$C_{ij}$ versus $o_{ij}$ for three targets

RankNet methodology · 4 of 4

Parameters and Gradient Descent Update

Parameters: network weights $w_k$ (and biases), learned by backpropagation.

Factored pairwise gradient (chain rule)

$$\frac{\partial C_{ij}}{\partial w_k}=\frac{\partial C_{ij}}{\partial o_{ij}}\left(\frac{\partial o_i}{\partial w_k}-\frac{\partial o_j}{\partial w_k}\right),\qquad \frac{\partial C_{ij}}{\partial o_{ij}}=P_{ij}-\bar P_{ij}$$

Weight update

$$w_k\leftarrow w_k-\eta\,\frac{\partial C_{ij}}{\partial w_k}$$

$\eta$ = learning rate. One forward pass per document, one shared backward pass.

Intuition

If $P_{ij}<\bar P_{ij}$ ($i$ should win but the net is not sure):

$o_i$ pushed up ↑ $o_j$ pulled down ↓

Python Implementation (scikit-learn + PyTorch)

import itertools, numpy as np, torch, torch.nn as nn
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

# DATA[query] = [(text, authority, click_rate, label 0-3), ...]
def featurize(query, docs):
    """x = [TF-IDF cosine, authority, click rate]"""
    texts = [d[0] for d in docs]
    vec = TfidfVectorizer().fit(texts + [query])
    sim = cosine_similarity(vec.transform([query]),
                            vec.transform(texts))[0]
    X = [[s, d[1], d[2]] for s, d in zip(sim, docs)]
    return np.array(X, np.float32), np.array([d[3] for d in docs])

class RankNet(nn.Module):          # one net, shared by both docs
    def __init__(self, d=3, h=8):
        super().__init__()
        self.f = nn.Sequential(nn.Linear(d, h), nn.ReLU(),
                               nn.Linear(h, 1))
    def forward(self, x):
        return self.f(x).squeeze(-1)       # o = f(x)

def make_pairs(X, y):              # (more relevant, less relevant)
    return [(X[i], X[j])
            for i, j in itertools.permutations(range(len(y)), 2)
            if y[i] > y[j]]
def train(seed=0, epochs=300, lr=0.01):
    torch.manual_seed(seed)
    P = [p for q, docs in DATA.items()
           for p in make_pairs(*featurize(q, docs))]
    xi = torch.tensor(np.stack([p[0] for p in P]))
    xj = torch.tensor(np.stack([p[1] for p in P]))
    net, loss_fn = RankNet(), nn.BCEWithLogitsLoss()
    opt = torch.optim.Adam(net.parameters(), lr=lr)
    for _ in range(epochs):
        opt.zero_grad()
        o_ij = net(xi) - net(xj)                   # o_i - o_j
        loss = loss_fn(o_ij, torch.ones_like(o_ij))  # P_bar = 1
        loss.backward(); opt.step()                # gradient step
    return net

def pair_acc(score, y):
    ok = [score[i] > score[j] for i, j in
          itertools.permutations(range(len(y)), 2) if y[i] > y[j]]
    return float(np.mean(ok))

def ndcg_at_k(score, y, k=3):
    g = lambda r: ((2.0**r - 1) /
        np.log2(np.arange(2, len(r) + 2)))[:k].sum()
    return g(y[np.argsort(-score)]) / g(np.sort(y)[::-1])

# --- rank the held-out test query ---
q, docs = next(iter(TEST.items()))
X, y = featurize(q, docs)
with torch.no_grad():
    s = train()(torch.tensor(X)).numpy()
print(np.argsort(-s), pair_acc(s, y), ndcg_at_k(s, y))

Dataset dictionaries DATA (5 training queries) and TEST (1 query) follow the structure on slide 10.

Discussion

Limitations and Method Comparison

When RankNet struggles

1Rank-position blindness

Swapping #1↔#2 costs the same as #500↔#501, ignoring top-heavy attention (NDCG)

2Training complexity

Pairs grow as $O(n^2)$ per query; slow without factored gradient accumulation

3Data and bias

Needs many labels; click logs carry position bias

Conclusion and Future Work

Main takeaways

  • Pairwise ordering removes the need for arbitrary score thresholds
  • Sigmoid probabilities + cross-entropy give smooth, outlier-resistant gradients

Where ranking models are used

  • Web search engines such as Microsoft Bing
  • E-commerce product search
  • Recommendation feeds
